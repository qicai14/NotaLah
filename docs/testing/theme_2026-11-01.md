## UI-TC2: axe in the browser

The R26 suite (#81) is not built, so axe-core 4.10.3 was injected into each page from jsDelivr with a script tag and run
as `axe.run(document, { resultTypes: ['violations'] })`, 2.5 s after load. Six screens at 1440 x 900 and 375 x 812, in
light and dark: 24 runs. Screenshots of the same runs are in `docs/screenshots/123/`. An earlier run found muted text at
4.4:1 on the active Inbox row (`surface-strong`); it was fixed in the tokens before these runs.

These runs and the screenshots came before review set dark `border` to #48484a and `accent` to #323234 (commit 0d5599e). Neither token is a text ground at rest, but they were not re-run on those values.

No run reports `color-contrast`. Results are the same at both widths and in both themes, except `region`:

| Screen | Violations |
|---|---|
| Feed | none |
| Inbox | none |
| Login | none |
| Welcome | none |
| Note | `aria-allowed-attr` (1 node, `#c-new-body`), `landmark-complementary-is-top-level` (1) |
| Editor | `landmark-one-main` (1), `region` (5 at 1440 px, 4 at 375 px) |

These four are not colour issues and are in markup the theme does not change. They are follow-ups, so axe is not fully
clean yet.

Limits: axe does not judge text over images or slides, and each page was checked in its first state only (no open menus,
sheets other than Login, or hover states).
